# 会议决议执行跟踪系统

把公司会议通过的决议记录成**可执行事项**并跟踪到归档：秘书整理草稿 → 主持人确认分派 →
责任人上传过程证据 → 验收人按决议原文核对 → 主持人裁定复议 → 归档检索。

- **存储**：SQLite 存决议、子项与版本链；本地目录 `data/attachments/` 存证据附件
- **提醒**：进程内后台线程扫描到期/逾期待办（无外部调度器）
- **消息**：模拟适配器，不真正外发，每条消息返回模拟回执（`SIM-<CHANNEL>-xxxxxxxx`）
- **零依赖**：仅使用 Python 3.10+ 标准库，前端为原生 HTML/CSS/JS

## 一条命令启动

```bash
./run.sh                 # 默认 http://127.0.0.1:8000
PORT=8123 ./run.sh       # 自定义端口
```

首次启动自动建库并载入演示案例（改期逾期、责任人离职改派、验收不通过复议、
两名验收人可现场触发并发冲突、撤销后待办回收、已归档含归档后附注、未确认草稿）。
重置数据：删除 `data/` 后重新启动。

打开页面后，右上角可切换**当前操作人**（赵铮=主持人、钱颖=秘书、孙磊/李岚=执行人、
郑彻/冯杉=验收人）。

## 六个交付视图

| 视图 | 内容 |
|---|---|
| 会议记录 | 原始会议记录，按议题折叠；决议回溯到来源会议 |
| 决议分派 | 列表显示责任人、期限、验收状态与子项汇总；详情把**决议原文与最新执行证据并排** |
| 待办 | 按人查看执行/验收待办，逾期标注天数；回收站保留撤销/改派/归档回收记录 |
| 证据提交 | 责任人 multipart 上传；同轮再传**替换**旧证据（旧文件留痕）；驳回后再传进入下一轮 |
| 验收复议 | 验收人对照原文核对；执行人申请复议；主持人裁定支持/驳回 |
| 归档检索 | 关键词检索已归档决议；归档后仅允许补充附注 |

消息回执可在「消息回执」视图查看，提醒线程每分钟扫描，启动即扫一次。

## 业务规则

- 同一决议的多项责任**分别跟踪**；决议汇总状态（待执行 / 进行中 n/N / 已完成）
  一律由子项验收结果实时计算，不存冗余状态
- **执行人不能验收自己的工作**（即使同时被登记为验收人）→ 403
- 两名验收人同时提交同一轮结论时，由数据库部分唯一索引裁决，后到者收到 **409 冲突**
  及先到结论信息
- 改期、离职改派、撤销、证据替换、验收不通过、复议裁定全部写入 `log` 版本链，
  任何记录不被覆盖删除（撤销/驳回/旧证据均保留）
- 撤销决议：未完成待办全部进入回收站并通知执行人；撤销后不能再传证据
- 归档前置条件：所有子项验收通过；归档后冻结，仅可补充附注
- 逾期事项同时显示**逾期天数**与**延期/改期原因**

## 测试

```bash
python3 -m unittest tests.test_system -v
```

覆盖：子项汇总状态随验收实时变化、逾期天数与原因、越权自验收 403、
非责任人/非验收人拦截、两名验收人并发提交（服务层线程 + 真实 HTTP 201/409）、
撤销后待办回收与版本链、离职改派旧待办回收/新待办开启、证据替换文件留痕、
驳回→下一轮重提、驳回→复议→通过双结论并存、归档冻结仅附注可写、
草稿/确认的秘书与主持人权限。

## 目录结构

```
app/
  db.py          # SQLite 模式（决议/子项/证据/验收/复议/待办/版本链）
  service.py     # 领域服务：状态机、权限、版本链、待办回收
  messages.py    # 模拟消息适配器
  reminders.py   # 进程内提醒线程
  seed.py        # 启动演示数据
  server.py      # ThreadingHTTPServer + JSON API + multipart + 静态服务
  __main__.py    # 入口
  static/        # 前端（白、炭灰、青绿）
tests/test_system.py
run.sh
```
