# 会议决议督办系统

把会议通过的决议记录成**可执行事项**：秘书整理草稿 → 主持人确认后分派 → 执行人上传过程证据 →
验收人按决议原文核对结果。全流程零依赖（Python 3.11 标准库 + SQLite）。

## 一条命令启动

```bash
python3 run.py            # 默认 http://127.0.0.1:8000
python3 run.py --reset    # 清空并重新载入演示案例（延期 / 复议 / 冲突 / 撤销 / 归档）
python3 run.py --port 8080
```

启动即自动：

1. 初始化 SQLite（`data/decisions.db`）与本地附件目录（`data/attachments/`）；
2. 载入一个三季度运营例会，含 **逾期改期、驳回复议、两名验收人并发冲突、证据替换、
   责任人离职改派、撤销回收、归档附注、草稿** 等案例；
3. 启动进程内到期/逾期提醒线程（消息进模拟适配器发件箱）。

页面右上角可切换"当前操作人"（秘书 / 主持人 / 执行人 / 验收人），越权操作由服务端拦截。

## 功能页面

| 路径 | 内容 |
|---|---|
| `/` | 决议总览：责任人、期限、**验收状态汇总（实时由子项计算）** |
| `/meeting` `/meetings` | 会议记录，原始全文 + **议题按 `<details>` 折叠** |
| `/decision?id=` | 详情：**决议原文 ‖ 最新执行证据并排**；子项、证据链、验收记录、版本链 |
| `/todos` | 待办，逾期**同时显示天数与原因**；撤销/已完成自动回收 |
| `/review` | 验收 / 复议队列（按验收人筛选，含历轮驳回后的新证据） |
| `/archive` | 归档检索（编号/原文/部门/负责人/附注关键字） |
| `/messages` | 模拟消息适配器发件箱（分派/改期/撤销/冲突/提醒） |

配色：白底、炭灰导航与正文、少量青绿点缀。

## 关键业务规则

- **同一决议多项责任分别跟踪**；决议汇总状态不落库，始终从子项计数实时计算
  （`pending / in_progress / in_review / conflict / done / revoked`）。
- **版本链**：改期、责任人离职改派、决议撤销、证据被替换、验收不通过——全部追加整行快照版本
  （`*_versions` 表，`version + parent_version` 成链），不做就地覆盖。
- **证据替换**：旧证据保留并 `superseded_by` 指向新证据，只能基于最新证据验收。
- **执行人不能验收自己的工作**（建项时负责人/验收人也不得相同）→ `PermissionDenied`。
- **两名验收人同轮同时提交** → 双方验收标记 `conflict`（保留各自原始结论）、子项挂起、
  通知主持人裁定 → 主持人采纳一方原始结论生效。
- **验收不通过 → 复议**：执行人补新证据，证据轮次 +1，验收人基于新一轮再验收。
- **撤销决议**：名下未结子项 `cancelled` 回收、从待办消失、提醒不再扫描；已通过的子项保留。
- **已归档决议只允许补充附注**，改期/改派/再提交证据/撤销一律拒绝。

## 存储

- SQLite：决议、子项、版本链、证据元数据、验收事件、附注、消息 outbox（见 `app/storage.py`）。
- 本地目录：证据附件原文件（`Database.save_attachment()`，文件名加时间戳防覆盖）。
- 提醒：`app/reminders.py` 进程内后台线程，无外部队列；改期后按新期限重新提醒。
- 消息：`app/domain.py` 中 `MessageAdapter` 只落库 `messages`，不外发。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

35 个用例，重点覆盖任务要求的四项：

- **子项汇总**：全通过=done、部分=in_progress、驳回=in_review、冲突优先、撤销项排除分母；
- **越权验收**：执行人验收自己 / 非负责人传证据 / 负责人=验收人，均被拒；
- **并发提交**：真实双线程屏障同时提交 → 冲突 → 主持人裁定恢复；同一验收人同轮不得重复投；
- **撤销回收**：子项 cancelled、待办清空、全新提醒器也不再发提醒。

另含版本链、证据替换链、驳回复议轮次、归档只允许附注、逾期天数与原因、HTTP multipart 上传
与附件下载等端到端用例。

## 代码结构

```
run.py              一条命令入口（初始化 + 种子 + Web + 提醒）
app/storage.py      SQLite schema / 连接事务 / 本地附件
app/domain.py       全部业务规则与状态机（Web 与测试共用）
app/reminders.py    进程内到期/逾期提醒
app/seed.py         演示案例（含真并发冲突）
app/web.py          http.server 界面 + 页面渲染 + 白/炭灰/青绿样式
tests/              unittest 领域测试 + HTTP 集成测试
```
